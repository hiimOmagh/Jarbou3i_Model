# UI audit — 2026-10-15

Scope: the whole interface on `main` at `2637507` (2.1.0-alpha.56 plus the
finished UIX-1 to UIX-4 overhaul), in Arabic, English and French, light and
dark, desktop and phone, and both exported reports.

## Method

| Source | What it covered |
|---|---|
| Deterministic probe (Playwright + axe-core, Chromium) | 12 cases (3 languages x 2 themes x desktop 1440 / phone 390) x 13 states: the five setup steps, the prompt preview, the command palette, both lenses' full case files with every disclosure open, Connections, the workspace panel, the review ledger and the canonical editor. Each state: every axe rule at every impact, target sizes (with extended hit areas), text under 12px, untranslated UI text, truncation, heading order, overflow, duplicate IDs. Plus cold-load performance. |
| Visual review (independent reviewer, 108 screenshots) | Every phone screenshot of the visual audit, en-light and ar-dark desktop, fr-light tablet, both reports in English desktop and Arabic phone. |
| Code reading | Each high finding was confirmed in the code or a screenshot before it was listed here. |

## Verdict

The base is strong:

- axe finds **no violation at any impact** in 120 of the 156 audited
  state-and-case combinations. The other 36 are the same moderate landmark
  rule in three dialogs (workspace, ledger, editor) across all 12 cases (L1).
- Every state has exactly one `h1`, no skipped heading level, no horizontal
  overflow and no duplicate ID.
- No English leaks into the French interface. In Arabic, the only Latin text is
  brand names and acronyms (JSON, HTML, API, TPS, NSI).
- RTL mirroring is correct almost everywhere: rails, steps, arrows, meters
  filling from the right.
- Dark and light themes have the same layout and come from the same tokens.
- Outside the relationship explorer, no text is under 12px and almost every
  target is 44px.
- Local performance: DOMContentLoaded 538 ms, LCP 364 ms, sample to results
  397 ms, two long tasks (122 ms at load, 129 ms on loading the sample).

The weak spots group into five themes:

1. **The relationship explorer was never migrated to the kernel.**
   `src/relationship-explorer.css` is 34 KB with 320 legacy-token uses and
   one kernel token. It is the source of nearly every small target and all
   small text.
2. **Code text in Arabic.** The JSON answer box takes the page's
   right-to-left direction.
3. **The "single next step" promise.** The header's next action lags the
   guided flow, and on a phone the first screen holds two primary buttons
   with the topic field at the fold.
4. **Consistency.** Status shapes, gate terminology, and the two reports'
   visual languages differ from surface to surface.
5. **Phone density.** Cards nest three deep, and control stacks push content
   below the fold.

   (ADR-0002 covers the UI only).

   were waived and remain unmeasured.

   - six replay baseline differences await your acceptance;

     judge;
   - the Biopolitical answer-size decision waits on the next corpus run
     ("measure first").
5. **Parser limits** offered but not chosen: the quadratic lead-in regex
   (4.5 s on a 100k-character line) and the duplicate repair label.
6. **Research tooling** (Agent Reach): two options are on file, web-research
   prompt rules or a local answer-checker CLI. You chose "nothing for now".
7. **Side findings** not acted on:
   - canonical v2 records mode "focused" for a research-depth reply that
     stated no mode;
   - the Arabic and French fixtures hold three English strings.
8. **The original brief: "serve novices and experts".** Experts have the
   palette, compact density and the JSON editor. Novices have the guided
   flow, but editing and review still require JSON (M11).
