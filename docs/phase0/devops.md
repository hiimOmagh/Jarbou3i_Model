# DevOps, CI, and Release — Phase 0 discovery

## 1) State (5 lines)
- CI workflow (`.github/workflows/ci.yml:18-232`) runs 18 jobs (1 no-browser, 15 browser shards across 4 engine targets, 1 evidence, 1 gate) consuming ~66 minutes of runner compute per run; GitHub Pages deploys only on main push (`.github/workflows/ci.yml:234`).
- Branch protection on `main` and `ux0-preview` uses legacy API with `strict: false` and `required_approving_review_count: 0` (`gh api repos/hiimOmagh/Jarbou3i_Model/branches/main/protection`), while the documented branch ruleset is disabled (`gh api repos/hiimOmagh/Jarbou3i_Model/rulesets`).
- The 2026-11-16 "owner approves, agent executes" policy (`docs/operations/release-process.md:11`, `CONTRIBUTING.md:72`) lacks execution automation: `.claude/harness/release-cut.sh` only supports simultaneous cut-and-merge and crashes if rerun on an approved PR.
- Approvals are disconnected across layers: GitHub PR review status is unenforced, `.claude/harness/release-cut.sh` never invokes `approved()` from `release-common.sh:15`, and `release-gate.cjs:57` condition 9 is a tautology that passes even if branch protection checks fail.
- Release tags (`v2.1.0-alpha.57`) trigger no CI or automation (`.github/workflows/ci.yml:3-7`); `gh release list` is empty (0 releases), and Cloudflare production deployments have no post-merge CI verification or header checks.

## 3) What is good (keep)

- Pinned containerized browser execution: CI runs all browser tests inside `mcr.microsoft.com/playwright:v1.64.1-noble` with `--user 1001` (`.github/workflows/ci.yml:48-50`), completely avoiding apt mirror stalls and ensuring reproducible browser environments.
- Strict CI script contract check: `tests/ci-script-contract-check.mjs` validates that workflow files, runner topology, sharding, and npm scripts match `package.json` and lockfile versions (`package.json:21`, `tests/ci-script-contract-check.mjs:1-287`).
- Fail-fast disabled on matrix: `fail-fast: false` (`.github/workflows/ci.yml:54`) ensures that failures in one browser shard do not abort remaining browser test runs, preserving complete diagnostic output.
- Granular per-shard debug artifact capture: Every failed browser shard uploads its own uniquely named artifact (`browser-debug-<leg>`, `.github/workflows/ci.yml:140-149`), retaining diagnostics for 7 days without overwriting.
- Clean isolation of release gate: `node .claude/harness/release-gate.cjs` cleanly evaluates 9 release preconditions (clean tree, CI runs, backlog rows, i18n checks, audit recency, owner confirmation) before any release branch can be merged.
- Controlled Pages deployment: GitHub Pages deploys exclusively from `main` pushes after both `No-browser gates` and `Browser gates` succeed (`.github/workflows/ci.yml:234-237`), using explicit curated build artifact `node scripts/build-pages-artifact.mjs`.
